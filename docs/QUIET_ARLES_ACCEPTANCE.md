## 性能证据与限制

同一 Linux 云主机、AMD EPYC、Chromium 154.0.8037.57、ANGLE SwiftShader、1600×900、DPR1；先后执行完全相同的 `旋转→上梯→C2→C0→跨越→门`。本轮最终画面性能测量提交为 `e4a0574`；其后改动是回退释放保障和发布/文档工具，不改变该画面的几何、灯光或动画循环。

| 指标 | 原 G2 | Quiet Arles |
|---|---:|---:|
| 完整路线观测 FPS | 8.35 | 6.87 |
| mean 帧间隔 | 119.67 ms | 145.41 ms |
| P95 帧间隔 | 233.40 ms | 266.70 ms |
| 路线墙钟时间 | 17.49 s | 20.09 s |
| 起始同视角 draw calls（renderer.info） | 32 | 42 |
| 起始同视角三角形（renderer.info） | 1,294 | 7,622 |
| 稳定画面 10 秒实际重绘 | 原持续渲染 | 0 帧 |

rAF 的约 16.64 ms 空闲调度间隔**不称作 60 FPS 渲染性能**；静态内容没有发生实际 GPU 重绘。renderer.info 不等于包含所有单独阴影 pass 的完整 GPU 调用数。原有每帧 dt 上限保留，因此在软件渲染下动画墙钟时间会增加。

首版中间记录显示额外 draw calls 与阴影成本，已按实际测量合批、移除多余补光、缩小阴影范围并用 1024 软阴影。不是用裁掉物体换性能：新增测试检查四个转态全部可见投影物顶点都位于阴影相机内。未引入 LOD、后处理、异步加载器等复杂系统。仍需实机 GPU/手机测量后决定进一步优化，不用云端数值冒充物理设备预算通过。
